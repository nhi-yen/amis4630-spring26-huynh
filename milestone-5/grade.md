## 5. Code Quality Coaching (Non-Scoring)

- **Admin password in source code**: [DataSeeder.cs](backend/BuckeyeMarketplaceApi/Data/DataSeeder.cs#L52) hardcodes `"Admin@1234!"`. For production, consider reading seeded admin credentials from user-secrets or environment variables to avoid having passwords in version control, even if they're for seed data.

- **Token storage in localStorage**: [api.ts](frontend/src/services/api.ts#L10) and [AuthContext.tsx](frontend/src/contexts/AuthContext.tsx#L99) store JWT in `localStorage`, which is accessible to any JS on the page (XSS vector). For higher security, consider `httpOnly` cookies or in-memory-only token storage with a refresh token flow.

- **Price as string in admin form**: [adminApi.ts](frontend/src/services/adminApi.ts#L19) defines `price` as `string` in `ProductCreateRequest`. The backend receives this and may rely on model binding to parse it. Explicit conversion to `number` before sending would be more robust and type-safe.

- **Confirmation number generation loop**: [OrdersController.cs](backend/BuckeyeMarketplaceApi/Controllers/OrdersController.cs#L112-L125) uses a while-true loop with database checks for uniqueness. Under high concurrency this could be slow. A GUID-based approach or database-generated sequence would be more scalable.

- **401 interceptor side effect**: [api.ts](frontend/src/services/api.ts#L35-L43) redirects to `/login` via `window.location.href` on 401 when a token exists. This is a hard navigation that loses SPA state. Consider dispatching a logout action through the auth context instead.

## 6. Git Practices Coaching (Non-Scoring)

- **Commit granularity**: The workspace contains well-separated concerns across files (controllers, services, contexts, pages). Ensuring each logical feature (auth backend, auth frontend, order flow, admin CRUD) was committed separately helps reviewers and future debugging.

- **Branch strategy**: For a project of this scope, feature branches per milestone (e.g., `feature/m5-auth`, `feature/m5-orders`) merged via PR to `main` would provide better traceability and rollback capability.
